# Spec 11 — F11 控制台彩蛋 + 键盘秘籍

> 对应 PRD §F11。术语遵循 `CONTEXT.md`（彩蛋）。_Avoid_：游戏、隐藏功能（泛称）。
> 发布为 GitHub Issue #12（`idonhve/whoami`，标签 `ready-for-agent`）。依赖 Spec 00（地基）、Spec 05（埋点 SDK）。

## Problem Statement

技术型访客打开 F12 是高意向信号（想看实现、验证实力），常规网站浪费了这个"对暗号"的机会；彩蛋能促成传播，但实现不当会拖累正常性能。

## Solution

面向控制台埋设彩蛋：console 输出 ASCII art 站主签名 + 招聘联系方式 + "你打开了控制台，说明你是对的人"类文案；键盘秘籍（`↑↑↓↓←→←→BA`）触发全站特效（粒子雨/主题切换）并有视觉反馈。彩蛋零运行时开销（事件监听惰性绑定），触发计入 `easter_egg` 埋点。

## User Stories

1. 作为技术同行，我希望打开控制台看到 ASCII art 签名与招聘联系方式，以便"会心一笑"并顺手拿到联系方式。
2. 作为技术同行，我希望触发键盘秘籍后有全站粒子雨/主题切换的视觉反馈，以便截图传播。
3. 作为技术同行，我希望彩蛋不影响任何正常功能与性能，以便玩彩蛋不付代价。
4. 作为访客，我不知道彩蛋存在也能正常使用全站，以便无感知零干扰。
5. 作为站主，我希望彩蛋触发计入埋点，以便量化传播效果。
6. 作为站主，我希望秘籍触发可重复，以便访客可以玩多次。
7. 作为站主，我希望文案与联系方式集中一处维护，以便换联系方式只改一处。

## Implementation Decisions

### 模块边界与依赖

- 前端：`src/easter-egg/`（console 输出、秘钥序列监听、特效触发器——粒子雨与主题切换复用 Spec 01 的全局层与主题 token）；公共文件改动点：`src/App.vue`（挂载本模块初始化一行）。
- 惰性绑定（零运行时开销承诺）：console 彩蛋在应用挂载后一次性输出；秘籍监听**不是常驻 keydown 监听**——首次按键进入"候选序列"状态才开始比对（或用防抖的轻量序列匹配器，保证非候选按键路径 O(1) 退出）。
- 秘籍：`↑↑↓↓←→←→BA`（连续 10 键，窗口期内完成；触发后重置状态可再次触发）；特效二选一或叠加：全站粒子雨（轻量 canvas，非 3D）+ 主题强调色切换（复用 Spec 10 的 theme token）。
- 视觉反馈：触发瞬间有明显的全屏反馈（粒子雨 + 短 toast `> konami ✓`），持续数秒后粒子雨自然消散。
- 依赖：Spec 05 tracker SDK（触发时上报 `easter_egg`，`detail: {type: "console" | "konami"}`——console 彩蛋在被"看到"时无法可靠探测，仅秘籍触发计入；console 输出本身不打点，避免误报）。
- 无后端代码、无表、无新增 API。
- 不占用任何页面 3D 锚点配额（彩蛋特效是瞬时全局层，非页面锚点）。

### API 契约

无新增。消费 `POST /api/track/event`（`easter_egg`）。

### 表结构

无。`easter_egg` 事件写入 Spec 05 的 `track_event`。

## 验收标准（逐条搬运自 PRD §F11）

* [ ] 控制台输出 ASCII art 站主签名 + 招聘联系方式 + "你打开了控制台，说明你是对的人"类文案

* [ ] 键盘秘籍（如连按 `↑↑↓↓←→←→BA`）触发全站特效（如粒子雨/主题切换），有视觉反馈

* [ ] 彩蛋不影响任何正常功能与性能（零运行时开销，事件监听惰性绑定）

## Testing Decisions

- 测试缝：组件/模块行为 + 性能断言，不测 canvas 粒子物理细节。
- 模块测试：应用挂载后 console 收到一次彩蛋输出（spy console，断言含签名与联系方式文案）；秘籍完整序列触发特效标志与埋点调用；错误序列中途重置；连打两轮可触发两次；普通按键不触发。
- 性能断言（验收第三条的可测化）：未开始输入序列时，全局无 keydown 处理逻辑执行匹配（用 spy 断言匹配器未被调）；生产构建包体积中彩蛋模块 chunk ≤ 数 KB 级。
- Playwright：模拟完整秘籍键序 → 页面出现反馈元素；`Ctrl+K` 等正常功能在彩蛋触发后仍可用（无相互干扰）。
- 无障碍：彩蛋纯装饰性，不抢焦点、不改变 DOM 语义。

## Out of Scope

- 多套秘籍体系与彩蛋管理后台。
- 彩蛋文案配置化（一期硬编码于模块常量；文案素材来自 `docs/content/`）。
- console 输出的访问探测统计（技术上不可靠）。

## Further Notes

- ASCII art 与联系方式文案集中放在模块顶部常量对象中，换文案/联系方式只改一处（对应第 7 条用户故事）。
- 粒子雨用 2D canvas 轻量实现（数量有上限、数秒自动停止），避免动用 Three.js 突破每页一个 3D 锚点的 PRD 红线。
