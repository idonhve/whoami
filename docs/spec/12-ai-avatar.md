# Spec 12 — F12 AI 聊天分身（二期占位）

> 对应 PRD §F12（明确标注"二期"）。术语遵循 `CONTEXT.md`（AI 分身）。
> 发布为 GitHub Issue #13（`idonhve/whoami`，标签 `ready-for-agent`）。
> **⚠ 占位册：本 Issue 不在阶段 3 并行窗口认领范围内，待一期上线（M5 后）视流量由站主决定启动。当前勿开工。**

## Problem Statement

（二期）面试官想即时了解"这个人技术细节/项目背景/工作偏好"时，只能留言等人回复；高频问题重复消耗站主时间。

## Solution

（二期终态）右下角悬浮终端图标，点开与"站主 AI 分身"终端风聊天窗对话，流式输出；基于预置简历语料（数据库维护的 Q&A 与个人资料）接入 LLM API 回答面试官常见问题；无法回答时引导留言板留言、不编造事实；对话轮次计入埋点。

## User Stories（二期，占位不验收）

1. 作为面试官，我希望点击右下角终端图标与站主 AI 分身对话，以便即时获得高频问题答案。
2. 作为面试官，我希望回答流式输出且为终端风聊天窗，以便体验与全站一致。
3. 作为面试官，我希望分身回答基于真实简历语料、答不出就引导留言，以便不被编造内容误导。
4. 作为站主，我希望 Q&A 语料在后台维护，以便分身知识随我更新。
5. 作为站主，我希望 LLM 密钥只在服务端保管，以便密钥不下发前端。
6. 作为站主，我希望对话轮次计入埋点，以便量化分身的实际价值。

## Implementation Decisions

### 模块边界与依赖（二期细化，当前仅占位）

- 预留边界：前端 `src/views/chat-widget/`（悬浮图标 + 聊天窗）；后端 `module/aiavatar/`（LLM 接入、语料拼装、流式输出）。
- 已知约束（自 PRD 搬运）：LLM 密钥服务端保管（env 注入，同 PAT 处理方式，不入库不下发前端）；语料来自数据库维护的 Q&A 与个人资料（新增表二期设计，暂不占用 12 表清单）；对话轮次写入 `track_event`（事件类型二期新增如 `ai_chat_turn`，需在 Spec 05 事件枚举追加）。

### API 契约（二期细化，占位）

- 方向已知：`POST /api/chat`（SSE 流式）+ `GET /admin/api/chat/qa`（语料管理）。细节（鉴权策略、限流、上下文轮数、Token 预算）二期启动时先出细化 spec 再实现。

### 表结构（二期设计，暂不建）

- 二期新增语料表（Q&A、个人资料），不进当前 12 表清单；启动时走独立迁移区间（V170+）。

## 验收标准（PRD 原文为"二期细化，先占位"，逐条搬运）

* [ ] 对话 UI 为终端风聊天窗，流式输出

* [ ] 接入 LLM API（密钥服务端保管，不下发前端），语料来自数据库维护的 Q\&A 与个人资料

* [ ] 无法回答时引导用户留言板留言，不编造事实

* [ ] 对话轮次计入埋点统计

## Testing Decisions

二期启动时随细化 spec 定义（外部行为优先：流式契约、密钥不泄露断言、拒答转引导路径）。

## Out of Scope（一期）

- 一期不实现任何 F12 功能、不建表、不引入 LLM 依赖。
- 不做语音/多模态分身。
