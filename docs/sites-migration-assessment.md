# 完全使用 Codex Sites 部署：适配评估

状态：历史可选方案，未采用。站主现已选择 Sites 前端 + Render 后端 + TiDB 数据库，保留 Java；实际部署流程见 `docs/deploy-sites.md`。

## 目标

前端、后台接口、业务数据与上传文件均托管在 Sites 管理的云端资源上。站点访问不依赖站主电脑开机、本地开发服务器或内网穿透；不继续采用 Render / TiDB 部署流程。保持现有访客页面和管理员业务功能。

## 已核实的限制与范围

现有前端为 Vue 3 + Vite，可以发布静态资源。后端为 Java 17 / Spring Boot，依赖 MySQL、Java 图片处理与离线 IP 查询。Sites 的服务端部署要求 Cloudflare Workers 兼容的 JavaScript 模块，不能直接运行现有 Java JAR 或 Docker Compose。

仓库包含 13 张业务表，以及 47 个控制器方法映射（未将 class-level 路径计作接口）。因此这次工作属于后端架构迁移，需要重新实现和验证业务接口，单改部署配置无法完成。

## 建议架构

| 层 | Sites 方案 | 迁移要求 |
| --- | --- | --- |
| 前端 | 继续使用 Vue / Vite | 与 Worker 同源，沿用当前页面、路由与 API 调用契约 |
| API | TypeScript Worker | 实现现有 `/api/**`、`/admin/api/**` 和 `/uploads/**` |
| 结构化数据 | Sites 管理的 D1 | MySQL schema 转 SQLite；保留业务字段、索引、分页、校验和原子更新语义 |
| 文件 | Sites 管理的 R2 | 存简历 PDF、证书图片与缩略图，D1 保存元数据 |
| 密钥 | Sites 运行时 secrets | JWT 密钥、GitHub token；不写入源码和前端构建产物 |

复用当前 `.openai/hosting.json` 中已登记的 Site 身份，改为同时包含 Worker 与前端资产的部署。D1 / R2 仅声明逻辑绑定，真实资源由 Sites 配置。删除仅静态发布的配置前先验证 Worker 打包方式。

## 必须保持的业务行为

- 管理员登录、JWT 续签、失败次数和锁定、接口鉴权、敏感操作日志；上线初始化使用随机管理员凭据。
- 作品、精选作品、技术栈、工作经历、证书、简历版本和站点配置管理；精选作品最多 3 个，简历保留最近 3 个版本等约束继续在服务端执行。
- 访客留言、限流、管理员审核和回复、访问日志、行为事件与统计；访客接口不暴露邮箱、原始 IP 或后台私有配置。
- GitHub 同步由云端执行，保留手动触发、日志、运营字段保护和缓存展示；每日同步须在发布前验证 Sites 云任务或可用定时触发链路，不能依赖本地进程。
- 文件上传、简历下载、缩略图与图片压缩。Java ImageIO / Thumbnailator 需替换为 Worker 兼容实现，不能把同一原图当成缩略图来省略功能。
- IP 归属地保持离线解析优先；需验证 Worker 兼容的 xdb 查询方式及资源限制，不能悄悄改成第三方在线查询。

## 现有 ADR 的影响

- ADR-0001：保持后端同步和前端只读业务数据；MySQL 存储和 Spring 定时任务实现需要更新。
- ADR-0002：保留离线 IP 归属地原则，替换 Java 解析实现。
- ADR-0003：保留当前页面动效和首页 3D 锚点设计。
- 与 ADR-0004 的“文件体存 MySQL”决策冲突：改用 R2，因为 Sites 会管理对象存储资源，无需另建第三方存储账号；需在实际实施时追加 ADR 记录这一变更。

## 上线验证

验证管理员鉴权和锁定、公开配置白名单、业务 CRUD、留言限流、简历版本回滚及下载、证书实际图片处理、GitHub 同步、统计和日志。验证数据、文件在重新部署后仍存在，并验证生产状态成功、关键接口响应和访问链接。发布不能以假数据或只显示页面作为完整上线的替代。

当前未提供已有 MySQL 业务数据导出。如果本地数据库已有站主内容，需要在迁移实施前检查并安排导入，不能默认为空库。
